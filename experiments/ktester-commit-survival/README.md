# KTester commit-survival experiment

This experiment compares KTester-generated tests with developer tests frozen at `cd16988dd46ac7533771eb6856a5f56c7aeaffba` on Apache Commons Codec, following the prescribed first-parent commits on master and restricting reported survival and changed-line coverage to Base32, Base64, Md5Crypt, MurmurHash3 and Sha2Crypt. The fixed range is the first 539 rows after the anchor, ending at `f9808d1f01d3a4e08c0c46283ef447ee0af6e7d8`; its verified list and measurements are in `results/`, frozen developer sources and the method denominator in `dev/`, the focal population in `population/`, future generated tests in `generated/`, and reproducible commands in `tools/`. Part 1 makes no model calls. Range counts are produced by `python3 experiments/ktester-commit-survival/tools/check_commits.py --kt /Users/donggi/_projects/experiment-projects/KTester` and recorded in `results/commits-check.json`.

Part 3 verification rejects any raw process exit of `-9`. `tools/repair_phase_a.py` watches the running Phase A without interrupting its workers, quarantines killed measurements under ignored `work/quarantine/`, and waits for the full run before repairing missing groups with two workers. It verifies the full raw set, all 27 MurmurHash3Test methods in each repaired developer group, and byte/mtime preservation of healthy records before restarting `tools/finish_part3.py`. Quarantine manifests and repair verification are retained in `results/`. Do not run a duplicate controller; its progress is in `work/phase-a-repair.json`.

The continuation runs Phase B through `tools/run_coverage_guarded.py`, resuming with six workers and explicit Phase B JVM heap caps. A container OOM triggers worker termination, evidence quarantine and resume with four workers; the previous four-to-two fallback remains, retaining completed healthy groups. Another OOM at two or any uncorrected signal-9 record blocks aggregation. Run `python3 tools/selftest_raw_integrity.py` from this experiment directory for the isolated quarantine and recovery checks. Frozen inputs, method selection, timeouts and scoring are unchanged.
